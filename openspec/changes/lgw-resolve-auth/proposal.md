# LGW#222、MLP#1525／#1529、MyPMO#462：resolve 認證設計

## Why

**目的。** 現在連得到 4710 的人，都可以要求 Gateway 發出訂閱憑證。4710 開在**會合點**上（會合點：worker、Mac 與 Gateway 各自用 SSH 連過去的那台中間機器；請求在這裡轉手）。建議讓 Gateway 認出請求來自哪台已登記的 worker 或 Mac，並限制那個身分能做哪些操作。原有的 4710 通道保留不動。

**怎麼認。** 每台 worker／Mac 持有一把**簽章金鑰**（一對數位鑰匙：私鑰留在那台機器上，用來替每個請求「蓋章」；公鑰交給 Gateway 登記，用來核對章是真的）。章用的是 OpenSSH 內建的 `ssh-keygen -Y`（SSHSIG）；worker 直接用它建 sshproxy 隧道的那把金鑰蓋章，Mac 另發一把專用金鑰。Gateway 只接受**名冊**上有登記、而且沒被撤銷的章（名冊：Gateway 手上的一份清單，寫著「哪把公鑰屬於哪台機器、可以做哪些事」；名冊上的每個身分叫 **principal**，例如「某台 worker」）。名冊每改一次，版本號就加一，這個版本號叫**世代**；Gateway 不接受比已載入的更舊的世代，以免有人拿舊名冊讓已撤銷的鑰匙復活。Gateway 另外記一份**防重放紀錄**（記下「哪些章已經用過」的小資料庫），同一個章不能用第二次。

**分三段上線。** off＝照現在，不檢查；warn＝檢查並記下「如果開了會擋誰」，但還是照常放行，用來找出漏改的呼叫方；enforce＝真的擋。warn 和 off 都不是安全措施。

**這是 b 級設計**（b 級：新增或重構一整組功能，要本人同意才能實作）。非作者審查與本人同意前不實作。

## 做完後仍存在的風險與功能退步

- **擋得住誰。** 只有「手上沒有已登記金鑰或簽章能力的外人」會被擋。依現有同機權限推論，worker 裡任何能讀或借用簽章金鑰的程式，仍拿得到該 worker 被授權的憑證；因為沿用隧道金鑰，能用那台 ssh-agent 的程式也算在內，可能涵蓋 worker 內所有 agent，須請 MLP 實證。會合點仍看得到明文；建隧道的 SSH 連線若開了 agent 轉發，會合點還能借用金鑰蓋章，所以要求隧道不轉發 agent（請 MLP 確認）。
- **時鐘出錯的後果。** Gateway 那台的時鐘若錯超過 60 秒，那段時間所有簽章請求都會被擋（agent 拿不到模型）；時鐘校正後立刻恢復，不用換金鑰。兩種情況會拖得比較久：
  - （甲）客戶端和 Gateway 的時鐘**一起**跳到未來，校正後，**凡是故障期間成功送過請求的機器**都會繼續被擋，最長約等於時鐘跳的幅度。如果它們用同一個時間來源（同一台 NTP、或同一台實體主機上的容器共用時鐘），可能是**全部機器**，不是一台。處理方式有三種：等時間追上、換那些機器的金鑰，或由 root 用一個會留紀錄的指令一次放行這些機器（紀錄是用來查誰做的，root 改得了，不防竄改）。最後一種要先確認 Gateway 的時鐘已經校正，而且執行時要先停 Gateway，停的那一下所有機器都拿不到憑證；代價是：故障期間若有人在會合點偷存了簽過的請求，每則可以被多送一次（可能多發一次憑證）。
  - （乙）防重放紀錄壞掉或遺失：Gateway 不會自己重建，開了 enforce 時會拒絕啟動，要由 root 跑恢復指令；重建後約 1–2 分鐘內簽章請求會被擋。撤銷紀錄另外存放，重建時不受影響。若無法確認當時時鐘是否正確，再換受影響的金鑰。
  - 另一個剩下的小風險：章蓋對了、卻在被記成「用過」之前就被擋下的請求——原因可能是時鐘差、那台機器超過每分鐘的請求上限，或 Gateway 忙到逾時／紀錄庫故障——若被會合點偷存，之後可以被送一次（每則至多一次，內容是原本要做的事，可能是多發一次憑證）。會合點本來就能搶先轉送簽過的請求，所以這只是把同一個風險往後延。
- **維運負擔。** 撤銷與換鑰（裝新名冊）不用停 Gateway；但重建紀錄庫、重設水位這幾個恢復指令都要先停 Gateway，停的期間所有機器都拿不到憑證。第一次啟用前要由 root 跑一次初始化指令建立兩份紀錄庫；之後若紀錄庫檔被刪或換了硬碟，Gateway 不會自己建空的，要走恢復指令，也不能拿舊備份蓋回去。
- **功能退步。** 開 enforce 後：一般帳號跑 `llmgwctl usage` 會失敗（要 sudo）；一般帳號跑 `llmgwctl check` 時「已簽章檢查」那項顯示「待處理（需 root）」，不會顯示失敗；worker 重建後要等名冊更新才拿得到憑證（見第 3 項）；同一台機器一分鐘內的請求超過約 600 次時會被暫時擋下（429），稍等再送即可，這個上限之後依實際用量調整。

## What Changes

提出節點金鑰簽章協定、獨立本地名冊（撤銷永久保留、不可復活；撤銷紀錄與防重放紀錄分開存放）、防重放（每把金鑰各記水位——該金鑰已清掉的舊紀錄裡最晚的時間，更早的章一律拒絕——不讓伺服器時鐘一次出錯就全體停擺；檢查與記錄在同一筆資料庫交易內完成，也就是要嘛全做完、要嘛全不算；每把金鑰另有請求上限，超過回 429，一台灌量不會擠掉別台）、off→warn→enforce，以及本機管理工具的身分；先遷移所有呼叫者及健康探針。簽章格式為 SSHSIG（namespace `llmgateway`），與 MLP#1529 協商共用同一把隧道金鑰、但用不同 namespace；MLP 端的值與向量尚未定案。既有本人決定「不做應用層認證」（`openspec/specs/key-vault/spec.md:54-61`，gateway-v0 決定 5a；程式註解 `lgwd/http.py:12-13`）須經本提案覆議；#222 的 11-21 本人想法是新決策來源，批准前舊規格仍生效。spec 變更：新增 `resolve-auth`；修改 `key-vault`（改名為「應用層認證依模式」）、`subscription-registry`（稽核記 principal，即通過驗證的名冊身分）、`connectivity`（健康探針改 `/healthz`）。

## 不做

不實作、不部署、不讀私鑰或連真機；不改 4710/4711 或 #221 位址追蹤；不自行讀 MLP 的 node 資料；不提供端到端機密性、惡意同機程序隔離、按個別人員歸責、金鑰託管或自動核准註冊。warn/off 不是安全邊界。
